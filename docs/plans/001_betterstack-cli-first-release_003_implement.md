# Milestone 003 Implementation Guide — `bs monitors list` with pagination and monitor filters

Spec: `docs/plans/001_betterstack-cli-first-release_003_spec.md`. Milestone source: `docs/plans/001_betterstack-cli-first-release_milestones.md` (entry 003).

## Section 1: Context Summary

Milestone 003 turns `bs monitors list` from a "not implemented" vector into a working command on the 002 seams: one bearer-authenticated `GET /api/v2/monitors` request, optional `--page`/`--per-page`/`--url`/`--pronounceable-name`/`--team-name`/`--timeout` flags whose values pass through unchanged for upstream validation (omission sends no parameter), raw byte-for-byte success output on stdout with no appended newline, raw non-2xx-including-3xx bodies on stderr with exit 1, no redirect following, no retries, no auto-drain, and the 002 credential, timeout, and token-safety rules reused unchanged. All behavior is verified through the `runWithAPI` injection seam against mock loopback servers using only the dummy token; no live API is called. Constraints that bind every task: every shell begins with `unset BETTERSTACK_UPTIME_API_TOKEN`; the test toolchain is `GOTOOLCHAIN=go1.26.9 GOPROXY=off`; `verify-incident-id.sh` and `.wayfinder/` stay untouched; a minimal shared HTTP-helper refactor inside `cmd/bs` is allowed only if `monitorsGet`'s observable behavior does not change.

## Section 2: Implementation Checklist

All tasks live in package `main` (`cmd/bs`). Dependencies are sequential: A1 → B1 → B2 → B3 → C1. No task pair is parallelizable (single package, shared files). Follow TDD within each task: write the failing test first, then implement, then run the focused test. Mock servers use `httptest` on loopback and the fixed dummy token `dummy-token-for-tests`; the ambient environment is never read by tests.

### Slice A — `monitors list` parses its flags (enables every later slice: without a parser no request can be built)

- [ ] A1: Add `parseMonitorsListArgs` to `cmd/bs/monitors.go` with a `monitorsListArgs` value type carrying present/absent state per flag (pointer or equivalent sentinel per field): `page`, `perPage`, `url`, `pronounceableName`, `teamName`, `timeout` (default `defaultTimeout`, 30 seconds, same parse rules and invalid-value handling as `parseMonitorsGetArgs`). Flags accepted in any order; every flag consumes the next argument as its value; a flag with no following value, an unknown option (any leading-`-` token not in the list, including `--all`, `--pretty`, `--query`, `--help` in flag position), and any positional argument are errors naming the problem. Test alongside in `cmd/bs/monitors_test.go` (pure parser table test, no server): valid vectors for each flag alone and combined, any-order, repeated occurrence of one flag (each occurrence recorded), and error vectors from spec R1.2–R1.4, R6.1, R7. Verification: focused `go test -run TestParseMonitorsListArgs` passes under `GOTOOLCHAIN=go1.26.9 GOPROXY=off`.
- Depends on: none (slice A is first).

- [ ] B1: Add `monitorsList(args []string, stdout, stderr io.Writer, baseURL string, client *http.Client) int` to `cmd/bs/monitors.go`, mirroring `monitorsGet`'s structure on the same seams: parse args (A1); missing/empty `BETTERSTACK_UPTIME_API_TOKEN` → actionable stderr message naming the variable, exit 1, before any request (`BETTERSTACK_API_TOKEN` never read, spec R2); build the query string with the stdlib `net/url` query builder (`url.Values`), adding each present flag exactly once per occurrence with its value unchanged — `page`, `per_page`, `url`, `pronounceable_name`, `team_name` — and adding nothing when absent, including absent-with-empty-string-present sending the parameter with an empty value (spec R3.2); exactly one `GET <baseURL>/api/v2/monitors?<query>` with `Authorization: Bearer <token>`; redirect following disabled via `http.ErrUseLastResponse`; timeout context from the parsed `--timeout`; 2xx body written to stdout byte-for-byte with `stdout.Write` (no appended newline, no parsing — spec R4); every non-2xx including 3xx body written to stderr byte-for-byte with exit 1 and exactly one request (spec R5.1); local/network failures → one concise, actionable, token-free stderr message, exit 1 (spec R5.2); `redactToken` applied only to locally generated diagnostics, never to passthrough bodies (spec R5.3).
