# Milestone 007 Implementation Guide — First-release acceptance verification

Spec: `docs/plans/001_betterstack-cli-first-release_007_spec.md`. Milestone source: `docs/plans/001_betterstack-cli-first-release_milestones.md` (entry 007).

## Section 1: Context Summary

Milestone 007 is the release-readiness verification milestone over the complete first-release surface. It changes no product code, no help text, and no test behavior: the five commands (`bs monitors get`, `bs monitors list`, `bs incidents get`, `bs incidents timeline`, `bs incidents list`) are implemented, routed, and covered by the approved mock-API suite from milestones 002–006, and 007 proves that whole surface green under the pinned toolchain, maps every contract item of the approved acceptance shape (ticket 06) to the passing tests that verify it, runs the pre-publication local install smoke test from a clean checkout with an isolated `GOBIN`, and records the deferred release actions (post-tag remote version check, real-account check) verbatim as separately authorized, user-controlled steps. The durable record is the 007 checkpoint itself; no README or other documentation change is required or made. Constraints that bind every task: every shell begins with `unset BETTERSTACK_UPTIME_API_TOKEN` and `unset BETTERSTACK_API_TOKEN`; the toolchain is pinned to `GOTOOLCHAIN=go1.26.9 GOPROXY=off`; no tag, push, publication, live API call, or external modification happens; `README.md`, `LICENSE`, `.gitignore`, `verify-incident-id.sh`, and `.wayfinder/` stay untouched; the `safety_test.go` `TestMain` credential isolation and loopback-only network guard stay enabled and are not weakened or bypassed.

## Section 2: Implementation Checklist

Task checkbox rendering is gated: a task box renders `[x]` only after the checkpoint records that task's gate evidence. The checkpoint is the sole home of run state; the boxes below do not store state independently.

All tasks are verification and recording tasks in package `main` territory (`cmd/bs`) plus docs (`docs/plans/`); no task writes product source. Dependencies are sequential: A1 → B1 → C1 → D1. No task pair is parallelizable (single verification thread; later tasks consume earlier evidence).

- [x] A1: Run the mock-API acceptance sweep and record the per-command contract→test mapping in the checkpoint. Record in the checkpoint, for each of the five commands, the contract items of spec R1.2–R1.9 with the exact passing test names that prove each item — filters (including repeatable `--metadata` with duplicate-key rejection and `--team-name` passthrough), raw byte-for-byte stdout envelope with no appended newline, non-2xx-including-3xx raw stderr with exit 1, no redirects and no retries (one request), 30-second `defaultTimeout` default and `--timeout` override with invalid-value rejection, missing-token pre-request failure, the former `BETTERSTACK_API_TOKEN` name never read, token never printed/logged/stored (test evidence plus the product source audit: no `log` package use and no credential file write in product code), exit 0/1 only, and the absent-feature rejections (`--all`, `--pretty`, `--query`, typed metadata variants, monitor URL form). Verification: every focused group passes under the pinned toolchain; the checkpoint mapping is complete with no unmapped contract item.

### Slice C — pre-publication local install smoke test (the smoke slice: proves the clean-checkout install path the first release relies on)

- [ ] C1: Run the pre-publication local install smoke test from a clean checkout with an isolated `GOBIN`, recording every command and result in the checkpoint. Steps: (1) materialize the verified HEAD into a temporary directory outside the repository with `git archive HEAD | tar -x -C "$tmp"` (never into the working tree); (2) from that clean checkout run `unset BETTERSTACK_UPTIME_API_TOKEN; unset BETTERSTACK_API_TOKEN; GOBIN="$tmp/go-bin" GOTOOLCHAIN=go1.26.9 GOPROXY=off go install ./cmd/bs` and confirm exit 0 with the `bs` binary present under the isolated `GOBIN`; (3) run `"$tmp/go-bin/bs" --help` with both credential variables unset, confirm exit 0, human-readable help on stdout, empty stderr, and no network request; (4) remove the temporary directory and the isolated `GOBIN`; (5) confirm `git status --porcelain` afterwards shows only the preserved pre-existing untracked entries (`.wayfinder/` tree and `verify-incident-id.sh`) with no stray `bs` binary or build artifact in the tree. Verification: install exit 0, help exit 0, clean status, cleanup performed — all recorded in the checkpoint.
