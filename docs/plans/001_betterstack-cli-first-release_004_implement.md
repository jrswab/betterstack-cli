# Milestone 004 Implementation Guide — `bs incidents get <id-or-url>` with dashboard URL support

Spec: `docs/plans/001_betterstack-cli-first-release_004_spec.md`. Milestone source: `docs/plans/001_betterstack-cli-first-release_milestones.md` (entry 004).

## Section 1: Context Summary

Milestone 004 turns `bs incidents get` from a "not implemented" vector into a working command on the 002 seams: one bearer-authenticated `GET /api/v3/incidents/{incident_id}` request whose target is either an opaque bare incident ID or a full dashboard URL of the observed form `https://incidents.betterstack.com/team/<team-id>/incidents/<incident-id>`, resolved by narrow local parsing — exact https host and four-segment path shape only, terminal all-digits segment extracted as the API ID candidate, no fetch to the user-supplied host, no resolve/probe call, no team-segment validation; every other URL shape is rejected locally as invalid usage (exit 1, no request), while a wrong bare ID or a wrong extracted ID gets the ordinary raw non-2xx passthrough. Success output is the raw byte-for-byte body including `included` when the API sends it; the 002 credential, error, timeout, no-redirect, no-retry, and token-safety rules are reused unchanged through the shared executor `doMonitorsRequest`. All behavior is verified through the `runWithAPI` injection seam against mock loopback servers using only the dummy token; no live API is called. Constraints that bind every task: every shell begins with `unset BETTERSTACK_UPTIME_API_TOKEN`; the test toolchain is `GOTOOLCHAIN=go1.26.9 GOPROXY=off`; `verify-incident-id.sh` and `.wayfinder/` stay untouched; only the `incidents get` vector changes outcome (`incidents timeline` and `incidents list` stay not-implemented; monitors behavior is frozen).

## Section 2: Implementation Checklist

New product code lives in a new sibling file `cmd/bs/incidents.go` (package `main`); new tests in `cmd/bs/incidents_test.go`; the only pre-existing files touched are `cmd/bs/main.go` (one routing branch) and the regression test's case list. Dependencies are sequential: A1 → B1 → B2 → B3 → C1. No task pair is parallelizable (single package, shared seam). Follow TDD within each task: write the failing test first, then implement, then run the focused test. Mock servers use `httptest` on loopback and the fixed dummy token `dummy-token-for-tests`; the ambient environment is never read by tests.

- [x] A1: Add to `cmd/bs/incidents.go`: (1) `parseIncidentsGetArgs(args []string) (string, time.Duration, error)` mirroring `parseMonitorsGetArgs` — exactly one positional target, `--timeout` with the same duration grammar and invalid-value handling (`defaultTimeout` 30 seconds), unknown leading-`-` tokens rejected, missing target and extra positionals rejected with errors naming the problem (spec R1.1, R1.2, R7.1); (2) `resolveIncidentTarget(target string) (string, error)` implementing the narrow rule (spec R2): parse with `net/url`.Parse — if the result has a non-empty scheme (URL-form), require scheme `https`, `User == nil`, `Host == "incidents.betterstack.com"` exactly (no port), `RawQuery == ""`, `Fragment == ""`, `Opaque == ""`, and a decoded path of exactly the segments `["", "team", <team-id non-empty>, "incidents", <incident-id>]` with `<incident-id>` one or more ASCII digits, then return `<incident-id>`; any URL-form miss (wrong scheme, wrong host, port, userinfo, query, fragment, trailing slash, wrong segment count, empty team, non-numeric terminal segment) returns an error naming the problem (spec R2.1–R2.2); a scheme-less target returns unchanged as an opaque bare ID with no content validation (spec R2.1, R2.3).
