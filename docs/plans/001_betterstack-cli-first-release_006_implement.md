# Milestone 006 Implementation Guide — `bs incidents list` with the full documented incident filter surface

Spec: `docs/plans/001_betterstack-cli-first-release_006_spec.md`. Milestone source: `docs/plans/001_betterstack-cli-first-release_milestones.md` (entry 006).

## Section 1: Context Summary

Milestone 006 turns `bs incidents list` from a "not implemented" vector into the last working first-release command on the established seams: one bearer-authenticated `GET /api/v3/incidents` request with optional `--page`/`--per-page` passthrough as in 003, the named hyphenated filters `--from`, `--to`, `--monitor-id`, `--heartbeat-id`, explicit `--resolved`/`--acknowledged` booleans accepting both the documented equals forms (`--resolved=true`, `--resolved=false`, `--acknowledged=true`, `--acknowledged=false`) and the established space forms (`--resolved true`, `--resolved false`, `--acknowledged true`, `--acknowledged false`) with only the exact lowercase literals `true`/`false` valid, the repeatable `--metadata key=value` flag translated per pair into the documented nested query parameter `metadata[<key>][][value]` with duplicate keys rejected as invalid usage and the typed variants `metadata[key][][type]`/`metadata[key][][email]` absent, and optional `--team-name` passthrough with no token-type detection. Success and error behavior ride the unchanged shared executor (`doMonitorsRequest`): raw byte-for-byte stdout with no appended newline, raw non-2xx-including-3xx stderr with exit 1, no redirects, no retries, no auto-drain, the 002 credential rules, the 30-second `--timeout` default with duration override, and token-free local diagnostics. All behavior is verified through the `runWithAPI` injection seam against mock loopback servers using only the dummy token; no live API is called. Constraints that bind every task: every shell begins with `unset BETTERSTACK_UPTIME_API_TOKEN` and `unset BETTERSTACK_API_TOKEN`; the test toolchain is `GOTOOLCHAIN=go1.26.9 GOPROXY=off`; `verify-incident-id.sh` and `.wayfinder/` stay untouched; help text (including `incidentsListHelp`) stays unchanged; a minimal shared refactor inside `cmd/bs` is allowed only if the implemented commands' observable behavior does not change.

## Section 2: Implementation Checklist

All tasks live in package `main` (`cmd/bs`). Dependencies are sequential: A1 → B1 → B2 → B3 → C1. No task pair is parallelizable (single package, shared files). Follow TDD within each task: write the failing test first, then implement, then run the focused test. Mock servers use `httptest` on loopback and the fixed dummy token `dummy-token-for-tests`; the ambient environment is never read by tests (the `safety_test.go` `TestMain` guard stays enabled and is neither weakened nor bypassed; the only client sources are the established `newHTTPClient()` and guarded `testHTTPClient()` seams — no test injects a custom transport or dials `net.Conn` directly).

- [x] A1: Add `parseIncidentsListArgs` to `cmd/bs/incidents.go` with an `incidentsListArgs` value type carrying per-flag occurrence slices, mirroring `monitorsListArgs` (`cmd/bs/monitors.go`): `pages`, `perPages`, `froms`, `tos`, `monitorIDs`, `heartbeatIDs`, `teamNames` as raw string slices (values pass through unchanged, spec R1.6/R3.2); `resolveds` and `acknowledgeds` as validated-literal slices (each occurrence must be the exact lowercase `true` or `false`, accepted in the equals form `--resolved=true`/`--resolved=false`/`--acknowledged=true`/`--acknowledged=false` or the space form with the value in the following argument — any other value, including `True`, `TRUE`, `1`, `0`, `yes`, and an empty string, is an error naming the flag and the problem, spec R1.3); `metadatas` as key/value pairs parsed from `key=value` values where the first `=` splits key and value, the key must be nonempty, a pair with no `=` is an error, and an empty value is valid and kept (spec R1.4); `timeout` with the same duration grammar and invalid-value handling as `parseMonitorsListArgs` (spec R6.1).
