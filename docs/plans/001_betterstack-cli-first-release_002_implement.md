# Implementation Guide — 002: `bs monitors get <id>` end-to-end against a mock API

Spec: `docs/plans/001_betterstack-cli-first-release_002_spec.md` (requirements R1–R9). Milestone source: `docs/plans/001_betterstack-cli-first-release_milestones.md`, entry 002.

## Section 1: Context Summary

Milestone 002 turns the 001 skeleton's `bs monitors get` from a not-implemented stub into the first working command: read only `BETTERSTACK_UPTIME_API_TOKEN`, make exactly one bearer-authenticated `GET https://incidents.betterstack.com/api/v2/monitors/{id}`, print the 2xx body raw to stdout with no appended newline, print any non-2xx (including 3xx) body raw to stderr with exit 1 and no redirect following, bound the request by a 30-second default timeout overridable with `--timeout`, and give concise token-free stderr messages for local/network failures — exit codes 0 and 1 only. The 001 codebase already injects `stdout`/`stderr` into `run(args []string, stdout, stderr io.Writer) int` (`cmd/bs/main.go`); the new HTTP seam extends that established pattern with test-only base-URL and HTTP-client injection and no new user-facing configuration (spec R9). All tests are offline and deterministic against a local mock server and use only dummy token values; the go1.26.9 toolchain is required (`GOTOOLCHAIN=go1.26.9 GOPROXY=off`; local default `go` is 1.22.2). Milestones 003–007 and the untouched `verify-incident-id.sh` / `.wayfinder/` tree stay out of scope.

## Section 2: Implementation Checklist

One vertical slice, ordered. Every task is test-first (red → green) at the seams fixed by the spec: the argv/writer seam (`run`) and the test-only HTTP seam (R9). Verification command for every task: `GOTOOLCHAIN=go1.26.9 GOPROXY=off go test ./cmd/...` (plus the task-named focused test). No task may read a real token, call a live API, or add a user-facing flag/env var beyond `--timeout` on `monitors get`. Exact function/file names below are the planned surfaces; the executing agent may adjust internal names provided the R9 seam boundary and every acceptance check are preserved.

### Slice A — working end-to-end success path (enables every later task)

- [ ] A1 (enables the whole slice, spec R9): extend `cmd/bs/main.go: run()` with a test-only injection seam for the API base URL and the HTTP client; `main()` passes the production base URL `https://incidents.betterstack.com` and the production client. Existing `cmd/bs/main_test.go` tests and the `invoke` helper keep working unchanged. Test task: extend `cmd/bs/main_test.go` with a red test that points the seam at a local mock server and asserts a `monitors get` invocation reaches it — this proves the seam exists and is deterministic before any request logic lands.
- [ ] A2 (R1, R2): implement request construction and the credential channel — new `cmd/bs/monitors.go: monitorsGet()` called from `run()` for the `monitors get` vector: read `BETTERSTACK_UPTIME_API_TOKEN` only (`os.Getenv`); when unset or empty, print one actionable stderr message naming `BETTERSTACK_UPTIME_API_TOKEN` and return exit 1 with zero requests; otherwise issue exactly one `GET <base>/api/v2/monitors/<target>` with `Authorization: Bearer <token>`, the target passed verbatim as one terminal path segment. Argument validation stays ahead of the token check (spec R2 boundary). Test tasks in `cmd/bs/main_test.go`: mock server records method, path, and header (R1: bearer header carries the dummy token); unset token, empty token, and `BETTERSTACK_API_TOKEN`-set-alone each yield exit 1, stderr naming the new variable, empty stdout, and a zero request count (R2).
- [ ] A3 (R3): on a 2xx response, write the raw body bytes to stdout byte-for-byte with no appended newline; stderr stays empty; exit 0. Test tasks: a fixed byte sequence (including one without any trailing newline and one deliberately non-JSON) is reproduced with exact byte equality; trailing-newline absence is asserted explicitly (R3).

### Slice B — failure rules on the one-attempt request

- [ ] B1 (R4): on any non-2xx response — 3xx included — write the raw response body to stderr byte-for-byte with nothing added, write nothing to stdout, and return exit 1 without following the redirect (verified mechanism: `http.Client.CheckRedirect` returning `http.ErrUseLastResponse` returns the 3xx response with its body unclosed and makes no further request; see spec Section 1 stdlib facts). Test tasks: a redirecting mock (3xx) and representative 401, 404, 429, and 5xx responses with arbitrary non-JSON bodies each produce exit 1, exact body bytes on stderr, empty stdout, and a recorded request count of exactly one — the no-retry and no-redirect evidence (R4).
- [ ] B2 (R5, R8): implement `--timeout <duration>` on `monitors get` in `cmd/bs/monitors.go` (`--timeout` parsing shared through `cmd/bs/main.go: run()` argument handling): default 30 seconds; Go standard duration grammar; unparseable or non-positive values are invalid usage — readable stderr, exit 1, zero requests. Test tasks: a delayed mock server (delay far below 30 s in wall time) with a short `--timeout` fails with exit 1, concise token-free stderr, empty stdout, one request, no retry; the same server responding within the override succeeds (proves the override is applied, R5); `--timeout 0s`, `--timeout -5s`, and `--timeout nonsense` each exit 1 with a readable error and zero requests (R5, R8). The 30-second default itself is verified by review of the single timeout source (spec R5 boundary), not by a 30-second wait.
- [ ] B3 (R6): implement the local/network failure path — when no HTTP response exists (timeout expiry, connection refused, DNS/TLS failure), print one concise actionable message to stderr and return exit 1 with empty stdout; never include the token; never retry (R6; the wrapped `*url.Error` text is header-free per the spec's stdlib facts, so no invented redaction pipeline). Test tasks: a test against an immediately closed local port (connection refused) and the B2 delayed-server case both yield exit 1, non-empty stderr, empty stdout; with the dummy token in the environment the dummy value appears nowhere in either channel (R6, first R7 evidence).

### Slice C — acceptance sweep and regression

- [ ] C1 (R7, R8): token-leak sweep and 001 regression. Test tasks: run the success path, one non-2xx path, and one local-failure path with the dummy token set, asserting the dummy value appears on neither channel in any of them (R7 — the bearer header the mock observed is the only sanctioned token appearance); assert the existing 001 invalid-usage matrix still passes and that `bs monitors list`, `bs incidents get 123`, and the missing/extra positional errors of `bs monitors get` record zero mock requests (R8); assert `bs monitors get --help` still exits 0.
- [ ] C2 (whole-spec verification): run the full gate — `GOTOOLCHAIN=go1.26.9 GOPROXY=off go vet ./...` and `GOTOOLCHAIN=go1.26.9 GOPROXY=off go test ./...` on a clean tree — and inspect against every spec requirement R1–R9 and the milestone 002 acceptance line (success passthrough, each failure class, timeout override, missing-token, never-printed-token, exit codes 0/1 only). `git diff --check` passes. Every working-tree change is accounted for; `verify-incident-id.sh` and `.wayfinder/` remain untouched.

### Parallelism

None (spec Section 2): 002 is one vertical slice. A1 must land before A2; A2 before A3/B1; B2/B3 follow the request path; C1/C2 verify the assembled slice. No task may start before its predecessor's tests pass.
